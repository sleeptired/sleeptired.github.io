### 1. 팀원이 작업한 코드 중 세이브와 관련된 내용 분석

구현부터 시작하지 않고 **읽기 전용 분석 문서**를 먼저 썼습니다. 판단 기준은 하나였습니다.

> **"세이브 레코드가 없는 상태는 전부 레벨 기본값이나 빈 값으로 돌아간다."**
>
> 이 전제를 세우니 *"저장 안 되는 것"* 을 찾는 것이 곧 *"로드하면 사라질 것"* 을 찾는 일이 됐습니다.

그리고 **심각도를 "플레이어가 잃는 것"으로 매겼습니다.**

| 등급 | 예 | 이유 |
| :---: | :--- | :--- |
| 🔴 | 솥에 넣어둔 재료·완성품 | **실제 재화 손실.** 돈 주고 산 재료가 사라짐 |
| 🔴 | 퀵바의 미개봉 봉인석 | **다시 주울 수 없는 영구 잔해**가 됨 |
| 🟠 | 바닥 아티팩트 픽업 | 소실 + **배치분은 반대로 중복 획득** |
| 🟡 | 쓰레기 표시 이름 | 이름만 "쓰레기"로 돌아감 |

> **"저장이 안 된다"는 같은 문장인데 결과가 전혀 다릅니다.** 이름이 바뀌는 것과 돈이 사라지는 것을 같은 줄에 두면 **무엇부터 할지 정할 수 없습니다.**

**저장할 필요가 없는 것도 같이 적었습니다.** 진행 중인 제조 단계(불·젓기)는 복원 시 의도적으로 대기 상태로 두면 되고, 소문 캐시는 시드에서 재계산되고, 요정 존재 여부는 계약 플래그에서 파생됩니다.

> **"안 해도 되는 것"을 명시하지 않으면 점검 결과가 그냥 할 일 목록이 됩니다.** 21개 커밋 중 **대부분은 저장 수정이 불필요**했고, 그걸 근거와 함께 적어두니 **진짜 할 일이 8건으로 좁혀졌습니다.**

### 2. 제조 — 저장 코드 연결

가장 심각한 🔴 항목인데, 막상 열어보니 **팀원이 저장 함수를 이미 다 만들어 놨습니다.**

| 있던 것 | 빠진 것 |
| :--- | :--- |
| 저장 구조체 | `UCSSaveGame`에 **필드 없음** |
| 캡처·복원 함수 | 서브시스템이 **참가자 인터페이스 미구현** |
| 왕복 테스트 콘솔 명령 | — |

코드에 `"[백무송님] 저장 연결"` TODO가 네 군데 남아 있었습니다.

> **"기능이 없다"가 아니라 "연결이 안 됐다"** 였습니다. 그래서 실제 작업이 **필드 하나 + 인터페이스 구현 세 줄**이었습니다.
>
> 세이브를 **인터페이스 기반**으로 만들어 둔 덕을 봤습니다. 참가자는 **자동 수집**되므로 **등록 코드가 필요 없고**, 팀원은 *"자기 상태를 저장하는 함수"* 만 쓰면 됐습니다.

### 3. 복원 우선순위를 15로 둔 이유

여기서 **그냥 기본값으로 뒀으면 조용히 깨졌을** 지점이 있었습니다.

```
월드 핸들러(10) : 복원 전에 월드의 모든 상품·상자를 제거
제조(기본값 5)  : 그보다 먼저 솥 재료를 생성
               → 월드 핸들러가 그 재료까지 지움 → 재료가 또 사라짐
```

> 솥 재료는 **숨김 + 재고 집계 제외** 처리라 **월드 캡처가 건너뜁니다.** 그래서 제조 쪽에서 직접 생성해야 하는데, **제거보다 먼저 만들면 함께 지워집니다.**
>
> 그래서 우선순위를 **15(월드 핸들러보다 뒤)** 로 뒀습니다. **"제거가 끝난 뒤에 생성"** 이 보장됩니다.

**우선순위를 5 간격으로 띄워 둔 게** 여기서 값을 했습니다. 10 뒤에 끼울 자리가 있었습니다.

### 4. 테스트가 계획에 없던 단계를 만들었다

3단계(쓰레기 이름 저장)를 구현하고 테스트하다가 **다른 버그를 발견했습니다.**

> **퀵바에 넣어둔 쓰레기가 불러오면 퀵바에서 사라집니다.** 이름은 고쳤는데 **쓰레기 자체가 바닥으로 갔습니다.**

그래서 **3-1단계를 새로 만들어** 퀵바 쓰레기를 퀵바로 복원하도록 고쳤습니다. 월드 쓰레기 캡처에서 **퀵바에 든 것은 제외**하고, 퀵바 레코드에 **쓰레기 칸**을 추가했습니다.

> **점검 문서가 못 찾은 건 "코드만 읽었기 때문"** 입니다. 쓰레기 레코드에 이름 칸이 없다는 건 읽어서 알 수 있지만, **퀵바 복원 경로가 쓰레기를 바닥으로 보낸다**는 건 실제로 넣어보고 불러와야 보입니다.
>
> 그리고 **단계 번호를 3-1로 붙인 것**도 의도였습니다. 4단계로 밀면 원래 계획의 4단계와 번호가 어긋나고, **"3단계를 하다 나온 것"이라는 맥락이 사라집니다.**

### 5. "전부 제거 후 재생성"이 두 문제를 동시에 풀었다

문제가 **두 개**였습니다.

| 문제 | 증상 |
| :--- | :--- |
| 가챠로 나온 픽업 | 저장 안 됨 → **소실** |
| 레벨에 배치한 픽업 | 주운 뒤 저장·로드하면 **레벨이 다시 만들어 중복 획득** |

처음 떠올린 안은 *"획득한 배치 픽업 이름 목록을 저장해 로드 시 제거"* 였는데, **쓰레기에서 쓰던 방식을 그대로 가져오니 둘이 한 번에 풀렸습니다.**

```
캡처 : 월드의 픽업을 배치분·가챠분 구분 없이 전부 기록
복원 : 레벨이 다시 만든 픽업을 전부 제거 → 레코드에 있는 것만 다시 생성
```

> **이미 주운 배치 픽업은 저장 시점에 없었으므로 레코드도 없습니다.** 레벨이 다시 만든 건 제거되니 **중복 획득이 구조적으로 막힙니다.**
>
> **"획득한 목록"이라는 별도 상태를 둘 필요가 없어졌습니다.** 구분하려 하지 않고 **전부 같게 다루니** 구분 자체가 불필요해졌습니다.

그리고 **이 단계를 5단계보다 먼저 한 것**도 이유가 있습니다.

> 바닥 봉인석이 **정확히 같은 패턴**입니다. 픽업이 **더 단순한 대상**이라, **작은 범위에서 패턴을 먼저 검증**하고 5단계는 그대로 따라 하기로 했습니다.

⚠️ 대신 **대가도 적어뒀습니다.** 이 단계 이전에 만든 v5 세이브를 불러오면 **레벨 배치 픽업이 전부 사라집니다.** 그 세이브에는 픽업 목록이 없어 **빈 목록으로 읽히고, 복원은 배치분까지 제거**하기 때문입니다. 쓰레기를 추가했을 때와 같은 성질입니다.
