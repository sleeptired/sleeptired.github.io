# **[UE5] 타이틀 화면과 세이브 슬롯 3칸 연동**

오늘은 타이틀 화면에서 세이브 슬롯을 선택해 새 게임 또는 이어하기로 진입하고, 이후 영업 종료 자동 저장도 선택한 슬롯에 기록되도록 연결했습니다.

기존 세이브 시스템에는 저장·불러오기·삭제 기능이 있었지만, 실제 타이틀 UI와 현재 플레이 슬롯을 연결하는 처리가 필요했습니다. 이번에는 **슬롯 선택 → 레벨 이동 → 진행 데이터 복원 → 같은 슬롯에 자동 저장**까지 하나의 흐름으로 만들었습니다.

---

## **1. 자동 저장이 어느 슬롯에 기록되어야 할까?**

### **① 자동 저장 기능과 저장 대상은 별개**

기존 영업 종료 저장은 `SaveToAutoSlot()`을 호출해 `CS_Auto`에 기록했습니다. 타이틀에 슬롯 카드 3장을 연결해도 이 부분을 그대로 두면, 선택한 슬롯으로 이어하기는 가능하지만 이후 진행은 다른 파일에 저장될 수 있습니다.

따라서 **현재 플레이 중인 슬롯**을 별도로 관리했습니다.

```cpp
// 현재 플레이 중인 세이브 파일 슬롯
// 타이틀을 거치지 않았다면 None
UPROPERTY(Transient)
FName ActiveSlotName;
```

| 진입 방식 | 자동 저장 대상 |
| :--- | :--- |
| 타이틀 1번 슬롯 선택 | `CS_Slot0` |
| 타이틀 2번 슬롯 선택 | `CS_Slot1` |
| 타이틀 3번 슬롯 선택 | `CS_Slot2` |
| 본 게임 맵을 에디터에서 바로 실행 | 기존 `CS_Auto` |

`SaveToAutoSlot()`이 현재 슬롯이 있으면 그 슬롯을 사용하도록 변경했습니다. 영업 종료 함수는 이미 이 함수를 호출하므로 별도로 수정할 필요가 없었습니다.

**자동 저장은 저장하는 시점과 방식이며, 반드시 `CS_Auto`라는 파일을 뜻하는 것은 아닙니다.** 타이틀에서 선택한 슬롯에도 자동으로 저장할 수 있습니다.

<br>

### **② 레벨이 바뀌어도 슬롯 정보를 유지하기**

`UCSSaveSubsystem`은 `GameInstanceSubsystem`이므로 타이틀 맵에서 본 게임 맵으로 이동해도 유지됩니다.

* 타이틀: 선택한 슬롯 이름 설정
* 본 게임: 같은 서브시스템의 슬롯 이름으로 자동 저장

레벨에 종속된 액터에 슬롯 이름을 보관했다면 레벨 이동 때 사라질 수 있습니다. 이번 정보는 **현재 게임 세션 동안 유지해야 하는 상태**이므로 기존 GameInstance 서브시스템에서 관리했습니다.

<br>

## **2. 새 게임과 이어하기의 초기화 차이**

### **① 새 게임은 이전 세션의 상태를 비워야 한다**

같은 실행 세션에서 다른 슬롯을 진행한 뒤 빈 슬롯으로 새 게임을 시작할 수 있습니다. 레벨만 다시 열면 GameInstance에 남은 정보가 새 게임에 섞일 수 있습니다.

`StartNewGame()`에서는 다음 처리를 수행했습니다.

1. 슬롯 이름과 본 게임 레벨 확인
2. `PendingLoadData` 초기화
3. 누적 플레이시간 `BasePlayTimeSeconds` 초기화
4. `ActiveSlotName` 설정
5. 수첩·아티팩트 상태 초기화
6. 본 게임 레벨 열기

```cpp
// 이전 슬롯의 복원 데이터와 누적 시간을 초기화
PendingLoadData = nullptr;
BasePlayTimeSeconds = 0.0f;
ActiveSlotName = SlotName;

// 레벨이 바뀌어도 유지되는 수첩과 아티팩트 상태 초기화
Journal->ResetJournal();
```

위 코드는 핵심 처리의 축약 예시이며, 실제 구현에서는 GameInstance와 서브시스템을 확인한 뒤 호출합니다. `ResetJournal()`이 내부에서 아티팩트 초기화도 수행하므로 아티팩트 초기화 함수를 다시 호출하지 않았습니다.

**빈 슬롯 선택 직후에는 파일을 만들지 않습니다.** 첫 영업이 끝나 자동 저장되어야 슬롯 파일이 생성됩니다. 첫날 중간에 종료하면 빈 슬롯으로 남는 것은 현재 저장 정책에 따른 동작입니다.

<br>

### **② 이어하기는 레벨을 연 뒤 복원한다**

이어하기는 기존 불러오기 흐름을 재사용했습니다.

1. 슬롯 파일을 읽어 `PendingLoadData`에 보관
2. 선택 슬롯을 현재 슬롯으로 설정
3. 저장 헤더의 `LevelPath`에 해당하는 레벨 열기
4. 본 게임 GameMode가 다음 틱에 저장 데이터 적용

복원할 월드와 시스템이 준비된 뒤 데이터를 적용하는 구조입니다. 타이틀에서 시작하는 새 게임 레벨은 `GameLevel`로 지정하지만, **이어하기는 저장 데이터에 기록된 레벨을 사용**합니다.

> **배운 점**
> 레벨을 새로 열어도 GameInstance의 상태는 남을 수 있습니다. 새 게임 시작에서는 무엇을 유지하고 무엇을 초기화할지 명확히 정해야 합니다.

## **3. UMG 외형과 C++ 동작 연결하기**

### **① 기존 위젯을 C++ 클래스로 Reparent**

기존 위젯의 외형은 사용하면서 부모 클래스를 변경해 동작을 연결했습니다.

| 위젯 BP | C++ 부모 | 역할 |
| :--- | :--- | :--- |
| `WBP_SaveSlotCard` | `UCSTitleSaveSlotCardWidget` | 슬롯 상태 표시와 선택·삭제 요청 |
| `WBP_SaveLoadMenu` | `UCSTitleSaveMenuWidget` | 슬롯 목록 갱신, 진입과 삭제 처리 |
| `WBP_NewTitle` | `UCSTitleScreenWidget` | 메뉴 열기·닫기, 게임 종료 |

카드는 사용자 요청을 이벤트로 전달하고, 메뉴가 저장 서브시스템을 호출하도록 역할을 나눴습니다. 타이틀은 메뉴의 생성과 제거를 담당합니다.

### **② 이름과 변수 설정이 바인딩의 기준**

C++ 위젯 멤버와 디자이너 위젯이 연결되도록 자동 생성 이름을 정리하고 필요한 텍스트에 `Is Variable`을 켰습니다.

| 변경 | 목적 |
| :--- | :--- |
| `Btn_DeleteCancel`, `Btn_DeleteConfirm` | 삭제 팝업 버튼 연결 |
| `Txt_PrimaryAction` | 새로 시작·이어하기 문구 변경 |
| `Txt_StoreLevel`, `Txt_PlayTime`의 Is Variable | 저장 헤더 값 표시 |
| `WS_SlotState` 자식 순서 확인 | 0 = 저장 슬롯, 1 = 빈 슬롯 |

Reparent는 **카드 → 메뉴 → 타이틀** 순서로 진행했습니다. 메뉴가 카드의 C++ 타입에 의존하므로 카드부터 준비해야 합니다. 각 위젯은 컴파일 에러·경고 0을 확인했습니다.

<br>

### **③ 슬롯 상태에 따라 화면 바꾸기**

| 상태 | 카드 표시 | 주요 버튼 | 삭제 버튼 |
| :--- | :--- | :--- | :--- |
| 빈 슬롯 | 빈 슬롯 화면 | 새로 시작 | 숨김 |
| 저장 슬롯 | 일차·시각·자금·레벨·플레이시간 | 이어하기 | 표시 |

메뉴는 `CS_Slot0~2`를 조회해 카드 3장을 갱신합니다. 저장 파일과 메타 헤더가 있을 때 저장 슬롯으로 표시합니다.

레벨 전환을 시작하면 `bIsTransitioning`으로 카드·삭제·닫기 요청을 막아 중복 처리를 방지했습니다. 진입 실패 시에는 UI 입력과 커서를 복구하고 카드를 갱신하도록 했습니다.

<br>

## **4. 타이틀 전용 GameMode와 입력 설정**

GrayBoxMap은 프로젝트 기본 GameMode를 사용해 1인칭 캐릭터가 생성되고 있었습니다. 타이틀 전용 GameMode로 바꾸고 필요한 UI만 띄우도록 구성했습니다.

| 설정 | 값 |
| :--- | :--- |
| GameMode | `BP_CSTitleGameMode` |
| Default Pawn Class | None |
| PlayerController | `BP_CSTitlePlayerController` |
| HUD Class | None |
| 입력 모드 | UI Only |
| 마우스 커서 | 표시 |

PlayerController의 BeginPlay에서 `WBP_NewTitle`을 생성해 Viewport에 추가합니다. 카메라는 기존 타이틀 연출 액터가 설정하도록 했습니다.

**맵의 GameMode Override와 프로젝트 시작 맵 설정은 별개**입니다. 이번에는 GrayBoxMap을 직접 열어 PIE로 테스트했으며, Game Default Map과 패키징 맵 목록 설정은 후속 작업으로 남겼습니다.

## **5. 저장 시각이 9시간 늦게 표시되는 문제**

### **① UTC에서 지역 시간으로 두 번 변환**

오전 11시대에 저장한 슬롯이 오후 8시로 표시됐습니다. 저장값은 정상 UTC였지만 표시 코드에서 지역 시간 변환을 중복 수행했습니다.

1. `FDateTime::UtcNow()`로 저장
2. 표시 전에 UTC+9 오프셋 직접 추가
3. `FText::AsDateTime`이 기본 시간대 처리로 지역 시간 변환을 다시 수행

따라서 한국 기준 +9시간이 두 번 적용되었습니다.

### **② UTC 값을 그대로 표시 함수에 전달**

직접 더하던 지역 시간 오프셋을 제거했습니다.

```cpp
// AsDateTime이 지역 시간 변환을 처리하므로 UTC 값을 그대로 전달
Txt_DateTime->SetText(FText::AsDateTime(Header.SavedAtUtc));
```

저장 형식은 바꾸지 않고 표시 코드만 수정했습니다. 기존 세이브도 같은 표시 경로를 사용합니다.

**코드 수정은 완료했지만 빌드와 실제 카드 시각 확인은 남아 있습니다.** 빌드 후 PC의 실제 저장 시각과 카드 표시를 비교해야 합니다.

> **시간 처리 기준**
> 저장은 UTC로 통일하고, 지역 시간 변환은 표시 단계의 한 곳에서 담당하도록 해야 중복 변환을 피할 수 있습니다.
{: .prompt-tip }
